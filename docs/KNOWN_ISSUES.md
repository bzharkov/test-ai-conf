# Known issues

- **Лицензия OpenDB.** ТЗ называет ODC-By 1.0, но репозиторий BuildCores OpenDB (проверен
  2026-11, `LICENSE.txt`, `NOTICE.md`) распространяется под **CC BY-NC-SA 4.0**: только
  некоммерческое использование, ShareAlike для производных данных. README и футер указывают
  фактическую лицензию. Для коммерческого использования данные OpenDB брать нельзя.
- **Формат OpenDB отличается от предположений ТЗ.** Нет флага Wi-Fi у плат (выводится из названия,
  `wifi_inferred=true`), нет списка поддерживаемых радиаторов у корпусов (`radiator_support_mm=null`
  → AIO с такими корпусами не подбираются), нет рекомендованной мощности БП у видеокарт, цен нет.
  Много корпусов (~3000 из ~3800) отбрасываются из-за отсутствия обязательных полей — см. статистику
  `import_opendb.py`. Импорт проверен сухим запуском на реальных данных; запись в БД проверена на
  демо-каталоге.
- **Демо-каталог составлен по памяти** (характеристики плат/корпусов/кулеров вроде числа M.2-слотов,
  длин карт, высоты кулеров сверялись не с даташитами) и содержит 108 позиций вместо 15–30 на
  категорию. Цены — ориентировочные (демо). Перед реальным использованием сверьте данные.
- **Эмбеддинги.** В среде разработки `sentence-transformers` не ставился, использован
  детерминированный hash-векторизатор (в Docker-образе ставится e5-small, веса качаются на сборке
  best effort). Качество поиска аналогов с e5 отдельно не измерялось.
- **Режим LLM не прогонялся** (нет ключа OpenRouter): парсинг со схемой, объяснения и чат с реальной
  моделью проверены только на мок-клиенте. `python eval/run_eval.py --llm` заполнит этот режим.
- **Таблица производительности** (`perf_scores.csv`) — приблизительный относительный порядок по
  общеизвестным обзорам, не измерения. Для моделей вне таблицы — эвристика с `perf_estimated=true`.
- **Beam search** эвристический: оптимальность не гарантируется. На узком каталоге три варианта
  могут отличаться лишь двумя ключевыми компонентами.
- Минимальная игровая сборка в демо-каталоге стоит ≈ 55 700 ₽ (нет дешёвых видеокарт), поэтому
  запросы с меньшим бюджетом получают `over_budget`.
- `docker compose up` не запускался (в среде разработки нет Docker-демона). Проверено отдельно:
  `docker compose config`, Alembic-миграции и сидирование на локальном PostgreSQL 16 + pgvector,
  backend на реальных PG/Redis, фронтенд в Chromium (Playwright) на 360/768/1440 px.
- Rate limit и кэш при недоступном Redis переходят на память процесса (не общая между воркерами).
